# Research findings — neuro-symbolic assistant harness (2026 sweeps)

Compiled 2026-09-01. Source of record for every finding that shaped the design.
Design spec: `docs/superpowers/specs/2026-09-01-neuro-symbolic-harness-design.md` (written after this file).

Legend: **[ADOPTED]** shapes v1 · **[LATER]** designed-for, built in a later milestone · **[VALIDATES]** confirms an existing choice · **[DISCARDED]** considered and rejected.

## 1. Core architecture pattern

- **Neuro-Symbolic Agents for Regulated Process Automation** — arxiv.org/pdf/2606.13405 — **[ADOPTED]**
  Symbolic layer decides *what* (control flow, legal action space per state); neural layer decides *how* (typed output over unstructured input); a **mediation interface** between them validates LLM output against activity contracts and re-prompts with diagnostics. "Compliance-by-construction." → Our engine/emitter split + rejection loop.
- **Neurosymbolic Embodied Agents** — arxiv.org/html/2608.16794 — **[ADOPTED]**
  4B + structure beats 27B direct by 32–63pp. Constraints alone 32%, search alone 29%, combined 95.5% (superadditive). Residual failures concentrate in *state acquisition*, not planning → text→command grounding is the hard part. Rule: "priors decide where to look, not what is present" → facts enter symbolic state only after confirmation; IDs come from lookups, never model memory.
- **From Intent to Infrastructure (agent compilers, ISAC)** — arxiv.org/abs/2607.16269 — **[VALIDATES]**
  LLM slow-loop / deterministic fast-loop time-scale separation; verifiable IR.
- **Compiled AI** — arxiv.org/html/2604.05150 — **[DISCARDED]** (full compile-to-static-code)
  Zero LLM in control plane: 4.5ms vs 2004ms P50, 57× fewer tokens, 100% reproducibility. Too rigid for open-ended assistant traffic; numbers justify the *compiled-flow* subset only (see §6).
- **Ontology-to-tools compilation** — arxiv.org/pdf/2602.03439 — **[ADOPTED]**
  Compile constraints into tool *signatures* (narrow the emittable space) rather than post-checking. → ActionSpec-driven schema building.

## 2. Emitter (neural command layer)

- **XGrammar-2 / TagDispatch** — arxiv.org/html/2601.04426 — **[LATER]** (local backend)
  100% schema validity vs 22–67% unconstrained; 6× grammar compile, 7× e2e latency. Needs logit access → self-hosted only.
- **llguidance** — github.com/guidance-ai/llguidance, docs.rs/llguidance — **[LATER]**
  Rust-native constrained decoding engine (Earley, ~50µs/token); backend inside vLLM/SGLang/llama.cpp/OpenAI. Slot reserved behind `Emitter` trait. Hardware check 2026-09-01: i5-7300HQ + GTX 1050 → local inference not viable; cloud strict structured output instead (schema built per turn = the constraint channel).
- **When Correct Isn't Usable** — arxiv.org/abs/2605.02363 — **[ADOPTED]**
  SLMs: high task accuracy but 0% joint (correct AND valid) naive; constrained decoding can *degrade task accuracy* (structure strangles reasoning). Mitigation adopted: free-text `rationale` field FIRST in the proposal schema. AloLab result: emitter system-prompt optimization 84→95% output accuracy → later tuning lever.
- **The Constraint Tax** — arxiv.org/pdf/2605.26128 — **[ADOPTED]** (same implication as above)
- **Tool Attention / MCP tools tax** — arxiv.org/html/2604.21816 — **[ADOPTED]**
  Tool definitions >~70% of context → reasoning collapses, parameter hallucination. → Engine prunes legal set aggressively (fewest applicable tools per state), not merely filters illegal.
- **Constraint Weakening ("Must becomes Maybe")** — arxiv.org/html/2608.24569v1 — **[VALIDATES]**
  Prompt-stated constraints erode over turns → constraints live in symbolic guards, never restated in prompts.
- **BFCL v4 / SLM function-calling surveys** — arxiv.org/pdf/2510.03847 — **[VALIDATES]** small emitter + strict schema + validators ≈ large-model reliability.

## 3. Provenance, guards, safety

- **ARGUS (ArgumentGrounder)** — arxiv.org/html/2605.03378v1 — **[ADOPTED]**
  Independent convergence on our taxonomy: Copy/Normalize/Derive/Resolve/Ungrounded ≈ CopiedOutput/Transform/Transform/Resolve/Residual. ASR 28.8→3.8% at 1.24× tokens. Also: span trust labels (benign/anomalous).
- **Agent-Sentry** — arxiv.org/html/2603.22868v2; **NeuroTaint** — arxiv.org/abs/2604.23374 (P .921 / R .935); **Evidence-tracing survey** — arxiv.org/html/2606.04990 — **[ADOPTED]**
  Trust dimension on origins: `User / System / External`; min-trust propagation along provenance chains; **TaintPolicy** guard = side-effectful actions can't take externally-sourced args without confirmation. (Prompt-injection defense nearly free on top of provenance.)
- **SafeCommit** — arxiv.org/html/2608.04289 — **[ADOPTED]** (pattern only)
  Gate side-effectful actions; reversible mutations stageable as probes; 2.6% unsafe commits @ 97.4% task success. → optional `Tool::stage()` (dry-run returning described effect); confirmation prompt shows staged effect. Full calibrated-worlds machinery: not adopted.
- **Revisable by Design** — arxiv.org/pdf/2604.23283 — **[VALIDATES]** irreversible actions permanently shrink reachable outcomes → gate before execution.
- **TraceCompiler** — arxiv.org/abs/2608.02680 — **[ADOPTED]**
  Binding taxonomy (constant/user-input/copied/transform/residual); refuse-to-compile on under-determined side effects → fail-closed guards. Compilation itself: [LATER], §6.

## 4. Event log & memory

- **The Log is the Agent** — arxiv.org/abs/2605.21997; **ESAA-Conversational** — arxiv.org/html/2606.23752; **OpenHands SDK** — arxiv.org/pdf/2511.03690 — **[ADOPTED]**
  Unanimous 2026 pattern: flat append-only typed event log = source of truth; projections = rebuildable read models; forking via parent pointer; snapshots are a later optimization. Trie NOT the log structure; tries belong in derived structures (mining automata, Aho-Corasick span matching, llguidance internals).
- **Automata from Agent Traces (PrefixGuard)** — arxiv.org/html/2608.23670v1 — **[LATER]**
  DFA mined from flat traces; replay 0.003–0.015ms; next-step prediction + failure warning. Input = our flat log.
- Merkle decisions: content-addressed `ArtifactId` = SHA-256 (dedup, verifiable CopiedOutput) **[ADOPTED]**; `prev_hash` chain on events (tamper-evidence, ~5 lines) **[ADOPTED]**; full Merkle DAG (multi-device sync) **[DISCARDED]** until a second replica exists.
- Storage: SQLite (rusqlite, WAL) over JSONL — atomic appends on Windows, cross-session mining queries. Value index: HashMap; `aho-corasick` crate if span-matching volume demands.

## 5. Replier & context

- **Span-level hallucination over tool output** — arxiv.org/abs/2607.00895v1 — **[ADOPTED]**
  Reply model must receive execution trace WITH outcomes and refusal reasons, not just result payloads; forbidden from entities absent from trace.
- **Prompt caching as harness constraint** — yage.ai/share/prompt-caching-harness-constraint-en-20260404.html; digitalapplied.com cache-first guides — **[ADOPTED]**
  85–95% input-cost savings on hits; exact-prefix matching; rules: stable prefix, append-only, mask-don't-remove. Resolution of tension with Tool Attention: emitter = tiny context, favor narrowing (via schema param, not prompt body); replier = expensive, order stable-first (persona → facts → session summary → turn trace), append-only within session.
- **Persona drift** — ContextEcho arxiv.org/abs/2605.24279; Attractor States arxiv.org/pdf/2606.30571; SPASM arxiv.org/html/2604.09212v1 — **[VALIDATES]**
  Persona degrades over long raw-history sessions. Our structural mitigation: replier never sees raw accumulated history — fresh persona block + bounded projection per call. Rule: cap session-summary length; persona block always first (also cache-optimal).
- `ReplyPolicy`: Verbatim / Template / Generate — many turns skip the expensive model entirely.

## 6. Evolution (harness gets smarter) — kept amendments 1–3

- **Experience Compression Spectrum** — arxiv.org/html/2604.15877v1 — **[ADOPTED (fields) / LATER (jobs)]**
  L0 raw trace → L1 episodic (5–20×) → L2 skills (50–500×) → L3 rules (1000×+); bidirectional promotion/demotion; idle-time consolidation (no current system does it). Our map: log=L0, facts=L1, compiled flows=L2, guard policies=L3. v1 adopts: lifecycle metadata on `Fact` (confidence, usage count, last-validated, provenance) + `Consolidator` plugin slot (no-op v1).
- **Sleep-time compute** — letta.com/blog/sleep-time-compute (≈5× test-time compute reduction, 2.5× amortized cost); arxiv.org/abs/2605.26099; IdleSpec arxiv.org/pdf/2605.22154 — **[LATER]**
  Consolidator job list includes pre-computing next-turn projections during user think-time.
- **Closed-loop corrections** — Power Apps MCP closed-loop learning; PrefPO arxiv.org/pdf/2603.19311 — **[ADOPTED]**
  `Corrected` event kind in v1; corrections → facts immediately; in bulk → emitter-prompt adjustments (AloLab lever).
- **Failure learning** — AgentErrorTaxonomy arxiv.org/abs/2509.25370; structured reflection arxiv.org/html/2509.18847; inference-time self-improvement arxiv.org/abs/2606.31270; verified-before-write arxiv.org/html/2604.17658v1 — **[LATER]**
  Consolidator mines Rejected/ToolReturned{Err} patterns; **any distilled rule/patch committed only after replay-verification flips the logged failure outcome**. M4 replay harness is the hard dependency for all M5 self-improvement.
- **PASTE (speculative tool execution)** — arxiv.org/html/2603.18897v1 — **[LATER]**
  Mined control-flow + data-flow patterns → pre-execute predicted next tool during LLM generation; −48.5% task completion time; side-effect policy blocked 602/20k unsafe speculations. Precondition already in v1: `Pure` side-effect class; perform-stage interface must not preclude parallel speculative calls. Same mined structure serves compilation AND speculation.
- **Tool-making agents** — arxiv.org/abs/2607.08010v1; STEM Agent arxiv.org/html/2603.22359v1; Mem²Evolve arxiv.org/pdf/2604.10923 — **[LATER]**
  Evolution pass may draft new composite ActionSpecs (versioned, tested, offline). Governance rule: synthesized tools reach registry ONLY via human approval + config.
- **Escalation ladder (cheap→strong emitter cascade)** — UCCI arxiv.org/abs/2605.18796; arxiv.org/pdf/2605.06350 — **[DISCARDED]** per user decision 2026-09-01.

## 7. Interaction behaviors (sweep 4)

- **Clarification: act vs ask** — Knowing but Not Showing arxiv.org/abs/2605.25284 (LLMs recognize ambiguity but rarely ask); Information-Gain clarification arxiv.org/abs/2606.03135 (ask only when expected to improve downstream tool use); Ask or Assume arxiv.org/html/2603.26233v1 — **[ADOPTED]**
  `ask_clarification` is a first-class action in the LegalActionSet, and the ENGINE decides when it's available/forced: objective trigger = required arg unresolvable by provenance (would-be Residual where Residual is forbidden). Don't trust model self-assessed uncertainty (per Knowing-but-Not-Showing).
  **ASPI caution** — arxiv.org/html/2605.17324v1: clarification-seeking amplifies prompt injection (injected content can manufacture a "clarifying" question to the user). → Clarification prompts pass TaintPolicy: a question triggered by externally-sourced content gets flagged/blocked.
- **Observability** — OpenTelemetry GenAI semantic conventions (opentelemetry.io/blog/2025/ai-agent-observability); AgentTrace arxiv.org/pdf/2602.10133 — **[ADOPTED (light)]**
  v1: `tracing` crate spans in the engine loop mirroring event kinds; OTLP exporter = later plugin. Instrument to GenAI conventions, not vendor SDKs.
- **Proactivity** — PARE arxiv.org/html/2604.00842v1 (observe mode: wait | send_message, read-only tools); "Do Proactive Agents Really Need an LLM to Decide When to Wake?" arxiv.org/pdf/2605.30152 (symbolic triggers suffice); ProActor arxiv.org/html/2605.24900v1 — **[LATER, one v1 trait decision]**
  Proactive wake triggers are ENGINE-side (schedules, events), not LLM-decided — matches our symbolic-owns-control principle. v1 requirement: `Channel` trait must support outbound-initiated messages (push without an incoming turn), or Telegram reminders become a breaking change later.

## Design decisions log (user-confirmed)

1. General harness first; Tomáš (Telegram sales bot) becomes a config/plugin set later.
2. Cloud-only inference (hardware: i5-7300HQ, GTX 1050 — local not viable). Emitter constraint = per-turn strict JSON schema. llguidance backend slot reserved.
3. Components: Rust `Tool` trait + HTTP escape hatch (Windmill/n8n via config). Bevy plugin/builder pattern for assembly. WASM host possible later (JSON-shaped tool boundary preserved).
4. Channel: CLI/REPL first; Telegram later (teloxide).
5. Core: event-sourced (A) + Bevy-style `HarnessPlugin`/`HarnessBuilder`.
6. Log: flat SQLite; hash-chained events; content-addressed artifacts.
7. Kept evolution amendments 1–3 (consolidator, corrections+failure mining, speculation+tool synthesis); discarded emitter escalation ladder.
8. Crates: core / engine / provenance / llm / components-std / memory-sqlite / channel-cli / channel-telegram / app.
9. Milestones M1 skeleton → M2 real loop → M3 provenance+guards → M4 assistant-shaped (facts, artifacts, replay) → M5+ evolution pass, Telegram, Windmill pack, local backend, WASM.
